# P1 Linux 项目提示词框架

适用项目：Linux 端导航应用开发组（Linux PAL 适配）。提示词用于把具体任务交给 AI；它们是按需选用的模板，不代表已经开始开发、完成验收或确认技术选型。

## 1. 组合方式

每次任务由三部分组成：**通用开场 + 对应组员的专业角色与职责 + 本次工作流程**。角色选择依据 AGENTS.md 第 1.1 节，覆盖应用/语音/发布、数据/存储、Geo 算法、定位/导航和地图渲染；公共规则与文档维护使用项目工程协作助手角色。具体事实从项目文件读取，避免在各个模板中重复维护环境版本、进度或跨组协议。

| 文件 | 内容 | 使用时机 |
| --- | --- | --- |
| [start.md](start.md) | 统一上下文、任务输入字段、执行与输出约定 | 新对话、重开任务或交接时使用 |
| [members.md](members.md) | 1–5 号的专业角色、职责、边界和模块验收关注点 | 选择本人编号对应的一段 |
| [workflows.md](workflows.md) | 工程初始化、模块开发、算法方案对比、跨组联调、排错、阶段验收、交接 | 选择本次任务对应的一段 |

最短开场示例：

```text
我是 P1 Linux 组员 2。请先阅读 prompts/start.md，使用 prompts/members.md 中 2 号的职责，以及 prompts/workflows.md 的“模块开发”流程。
本次目标：实现第 1 次作业的数据导入链路。
验收：可以选择固定样例文件，显示解析进度、统计和列表；错误文件与取消操作有明确反馈。
请先核对实际仓库与环境；遇到未确认的 G1 格式，请展示接入选项并等待我的选择，再处理依赖该选择的部分。
```

上例用于说明填写方式；不会因阅读本文件就自动执行数据导入任务。首次创建工程由 1 号使用“工程初始化”流程。

## 2. 每次需要填什么

| 字段 | 填写内容 | 缺失时处理 |
| --- | --- | --- |
| 组员编号 | 1、2、3、4、5 | 当前对话未确认时询问；不要从 Git 作者推断 |
| 本次目标 | 一个能独立演示或验证的结果 | 先从作业中提出具体子任务，避免一次默认包揽整个项目 |
| 作业阶段 | 第 1/2/3/4 次，或公共维护 | 可从任务与 project.md 核对，不把阶段当作已完成状态 |
| 范围 | 允许修改的模块、公共接口影响 | 默认本人模块；必要公共改动先说明影响 |
| 验收 | 输入、操作、期望输出、边界场景 | AI 先提出具体标准；未知阈值标待确认 |
| 已确认事项 | 环境、接口 ID/版本、方案记录 ID | 从文件和当前对话复用已有确认，不重复询问 |
| 日志与 Git | 当前用户对记录、提交/上传的要求 | 以本次明确要求与有效项目规则为准，不视模板为上传授权 |

可选补充：错误日志、真实接口头文件/样例、数据规模、设备条件、时间限制。没有的内容写“未提供”，不必凭空补齐。

## 3. 事实来源与维护

- 当前任务依据：[Linux 任务书摘录](../docs/linux-assignment-reference.md)。旧任务与历史对话仅供追溯。
- 统一虚拟机与工具版本：[development-environment.md](../docs/development-environment.md)；约定已定，是否安装以实测为准。
- 分工、模块状态与接口：[project.md](../project.md)；实现细节以实际代码、配置和运行结果核对。文件之间有冲突时说明差异，不能悄悄选一个当作事实。
- 项目保存的协作约定：[AGENTS.md](../AGENTS.md)；其是否生效由当前用户要求和会话指令决定。提示词模板不能覆盖用户的新要求。
- 方案与试验：[decision_log.md](../decision_log.md)；历史对话：[ai_log.md](../ai_log.md)。没有确认、实测或可见记录就标未知。
- 项目处于规划阶段时，不能因模板提到目录、CMake 或测试就宣称它们已经存在。版本、构建命令、依赖和性能结果都要从实际环境确认。

任务结束时按实际结果维护项目状态与适用记录；不要复制一份新进度表到提示词里。人员职责变动时同步修改 members.md 与 project.md；新增工作类型时在 workflows.md 增加模板并更新本表。

## 4. 检查一次 AI 回复是否可用

应能回答：具体完成了什么；改了哪些文件；如何验证以及真实结果；Mock/未验证部分是什么；是否改变已有接口；下一步是否需要组员选择。代码存在、编译通过、模块测试通过、Linux 运行通过、跨组联调通过是不同证据，不可互相替代。
